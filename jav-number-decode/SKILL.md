# JAV 番号解密（从叙事文本提取隐藏番号）

从看似普通的叙事文本中识别并提取被伪装隐藏的 JAV 番号，输出按前缀分组的解码列表。纯推理技能，无脚本、无网络依赖。

## When to Use

- 用户发送一段叙事/数据/路线指引类文本，其中嵌入了字母组合 + 数字（如 `MIDA酒店574房间`、`i派想：852千米…`）
- 用户说「解密这段」「这串文字里藏了什么番号」

Don't use for: 已明确给出番号只需查片名/女优 → 用 jav-bangou-lookup-fc2；有图搜源 → acg-reverse-image-search。

## Prerequisites

核心前提：JAV 番号标准格式为 `前缀-数字`（前缀 2~5 个大写字母，数字通常 3 位，偶尔 2/4 位）。

## 解密方法一览

| 方法 | 说明 | 示例 |
|------|------|------|
| A. 连接词嵌入法 | 字母前缀拆入名词，数字用房间号/门牌号 | `MIDA酒店574房间` → **MIDA-574** |
| B. 拼音首字母抽离法 | 从拼音短语提取首字母作前缀（i 常作连接符） | `i派想`→IPX，`i派政治`→IPZZ |
| C. 散列字母拼合法 | 大写字母被汉字隔开，收集后拼成前缀 | `M国I城D省E区989号` → **MIDE-989** |
| D. 数据数字采掘法 | 「工程数据/说明书」中每个数字对应一个番号 | `需要852千米的路程…` → 各数字逐一配对前缀 |
| E. 路线数字采掘法 | 方向指引中的楼号/米数/楼梯号/房间号/书架/页码都是番号数字 | `317栋楼、014米、364楼梯…` → 每个对应一个 |
| F. 零位拼接法 | 两个相邻数字片段拼成一个 3 位数 | `电量剩余00` + `花3元` → `003` |
| G. 演员关联法 | 提及的「主厨/chef」人名即 JAV 演员名，辅助验证番号归属 | `主厨leah gotti` → LA/FBD 系番号佐证 |

## Procedure

### 步骤 1：扫描所有大写字母组合与拼音可疑词

抽取文本中连续或散落的大写英文字母、叠写（zz→ZZ），以及拼音首字母短语。完成标准：每个候选前缀都列出解码依据。

拼音首字母规则表：

| 文本 | 对应前缀 | 依据 |
|------|---------|------|
| i派想 | IPX | i + 派(Pai) + 想(Xiang) |
| i派政治 | IPZZ | i + 派(Pai) + 政(Zheng) + 治(Zhi) |
| zz打零号空洞 | ZZ | 叠写直接大写 |
| MIDA/MIDE… | 原样 | 地名连续大写字母 |

### 步骤 2：提取所有数字（含前导零）

- 保留前导零（`014米` → `014`，不是 `14`）
- 2 位数字可能有效（`41号` → `041` 或 `41`，看上下文）
- 超 3 位的数字单独提取
- 相邻片段可拼接成 3 位数（零位拼接法）

完成标准：文本中每个数字都被标记为「番号候选」或「普通数字」。完成。

### 步骤 3：字母 + 数字配对

- **A. 直接配对**：字母紧邻数字 → 直接拼（`MIDA酒店574房间` → MIDA-574）
- **B. 散落收集**：散落大写字母收集后与附近/末尾数字配对（`M国I城D省E区989号` → MIDE-989）
- **C. 统一前缀批量法**（最常见于数据/路线场景）：识别主题（如「造桥」「找书」），该主题下所有数字共享同一前缀。例：主题「i派想」→ IPX，数据 852, 901, 778, 660, 934 → `IPX-852 … IPX-934`
- **D. 双首字母混合**：从不同位置取两字母作前缀；上下文已确定的前缀优先于临时组合

完成标准：每个数字都归属到某个前缀，或明确标注「推测」。

### 步骤 4：特殊线索验证

- `主厨/chef + 人名`（如 leah gotti）= JAV 演员名，确认番号真实存在性
- 日料/西餐等语境佐证讨论的是 JAV 而非门牌号
- 不常见的字母组合无法确认时标注「推测」并提出疑问

### 综合示例

输入：

> 我在MIDA酒店开了574房间。i在停车场p停好车后打开了zz打零号空洞，但是我打到手机电量剩余00直接关机，只能去小卖部花3元去借充电宝。M国I城D省E区989号。（i派想）：世界最大的桥，需要852千米的路程，901千米的宽度…（i派政治）：这本书，在书店317栋楼，需要往前再走014米…

输出：`MIDA-574, IPZZ-003, MIDE-989, IPX-852, IPX-901, …`

## 输出格式

```markdown
## 解码结果
### [前缀] 系列
- **XXXX-000** — [来源简述，如"酒店房间号"]
- **XXXX-001** — [来源简述，如"路程数据"]

### 完整列表
XXX-123, XXX-456, …

### 后续操作提示
是否需要查询 / 下载其中某个番号？
```

## Pitfalls

1. **上下文一致性是关键**：并非所有数字都是番号。围绕同一主题（造桥、找书）的数字通常共享同一前缀——先定主题再配对。
2. 优先识别前缀，再匹配数字；一段文本可能同时含多个前缀（MIDA、MIDE、IPX、IPZZ…），逐个处理别混串。
3. 前导零必须保留；`014` ≠ `14`。
4. 不确定的组合宁可标「推测」，不要硬凑。
5. 解密完成后主动询问用户是否转入查询（jav-bangou-lookup-fc2）或下载模式。

## Verification

对照输入文本逐条复核：每个输出番号的前缀和数字都能指回原文具体位置；无法指回的标「推测」。全部番号都有出处即通过。
