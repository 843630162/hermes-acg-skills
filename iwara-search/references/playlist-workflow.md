# playlist 遗漏挖掘：完整流程与报告模板

SKILL.md「遗漏挖掘」六步的展开版。两列表的现成判据/同义词表/作者索引在 collection-themes.md。

## 1. 拉全量 + 特征卡

- 拉 playlist 全量：`/playlist/{uuid}?page=N&limit=32`，逐页 sleep ~0.25s，以空 results 终止；count/numVideos 可能大于实拉条数（已删/私密仍被计数，如标 242 实拉 229、标 142 实拉 132）——缺口写进报告（意味着候选里极少数可能其实已在列表）。
- 至少取前 40 条（能全量更好）。每条记五样：标题原文 / tags / 缩略图中性描述（制作方式 Koikatsu/MMD/Blender/VaM、场景、灯光色调、构图元素）/ 作者 / 时长。
- 四维统计（高频即特征）：标签频次（≥15% 核心、5–15% 辅助；区分题材/角色/制作标签）；标题关键词（中/日/英各一列，很多作者不打标签）；画面元素（剪影、帘子、隔板、磨砂玻璃、面纱、透明布料、舞台光…）；作者与系列（≥2 部 = 作者翻页种子名单）。
- 两个列表加一段「共同点/区别」。别按列表名猜内容（名为 veil 的列表实收异域舞娘）：先拉全部标题+tags 本地读一遍，从真实内容反推它到底在收什么。

## 2. 多语言同义词表（示例）

- 剪影/影姦系：silhouette、shadow、シルエット、影姦、隠姦、隐奸、影子版、カーテン越し、帘子、すりガラス（磨砂玻璃）、magic mirror、魔镜、MM号、glory hole、更衣室ダンス、試着室。
- 面纱/异域舞娘系：veil、ベール、belly dance、ベリーダンス、踊り子、舞娘、舞姬、arabian、アラビアン、egyptian、エジプト、Egyptian Trend、oriental dress、Exotic Dance、西域、异域、布料解算、薄纱、sheer。
- 新建：先从第 1 步标题/标签抽词，再补各语言写法与作者自创系列名；两列表现成表在 collection-themes.md。

## 3. 找候选（优先级从高到低）

0. **要「尽可能全」：整站快照本地匹配**（`iwara_snapshot.py update` → `search`，见 site-snapshot.md；建好一次、跨主题复用），再叠下面各流。
1. 运算符流：核心+同义 tags 逐个 `{tags}`；标题关键词流（注意 franchise 陷阱）。重点类型可一次跑上百个多语言词（2026-09 一期约 120 词、候选池 ~1.7 万）。
2. 作者系列翻页：高频作者全部作品过一遍（显示名先 resolve 成当前 username）——最易挖到同系列、同动作、不同版本（打码/无码、双视角、重传）。该任务抓了约 45 位作者全量。
3. 标签页：核心与同义标签逐个翻。
4. 外部引擎 `site:iwara.tv`：最后手段（前端渲染站，引擎几乎不收录；DDG html 端点连查几次后出异常验证、每次 sleep ≥2s；Bing 基本拿不到）。

候选池大时先按标题/标签/简介关键词粗筛再逐条判；全量数据存 JSON 供深挖。

## 4. 匹配判定 A/B/C/D

- A 标题或标签直接命中同义词表；B 简介命中（如简介写 シルエット、カーテン）；C 与列表已有同作者同系列、或同视频不同版本；D 同动作/同舞曲且画面元素一致（弱相关，标注、排最后）。
- 排序：A+B、A+C 在前；仅 D 最后；标签泛（只 ntr）而标题看不出 → 最多进「待确认」。
- 可选加强：候选缩略图过一遍按「画面是否真是该类型」再筛，报告注明哪些看过封面。
- 排除过滤：`otokonoko`+男娘丢；动漫风列表（Koikatsu/MMD/Blender）剔 VAM 写实风；**幼态角色不排除**（loli/shota/ロリ/幼/JS 及明显幼态角色照收）。

## 5. 去重与核验

- 按视频 id 与 playlist 全量 diff；记未登录不可见条目数进报告；逐条 `/video/{id}` 确认 active；403/私密单列。旧视频可能缺时长等字段，报告写「—」。

## 5.5 排名（可选加强）

- 热度榜：按 numViews；好评率榜：likes/views，设最低播放门槛（如 ≥2000）防小样本。
- 平滑点赞率 (likes + K·C)/(views + K)：C=全体平均点赞率、K=门槛值；快照在本地可直接算。

## 6. 报告模板（中文 Markdown，`iwara-<主题>-<YYYY-MM-DD>.md`）

1. 简介：方法、数据来源（跑了多少关键词/作者流、候选池多大）、各类数量、核验日期；用了整站快照就注明快照日期与条数。
2. 每类一张表：标题 | 作者 | 时长 | 标签 | 匹配理由 | 链接 `https://www.iwara.tv/video/{id}`，按匹配度排序。
3. 推荐关注的作者/标签/关键词（未逐条列出的注明大致数量，如「bl 布料系列还有 150+ 部」）。
4. 局限：搜不到/需登录/没看封面/剔除规则。

### 表格排版规范（交付前必做）

- 单元格值入表前先净化：`|` → `／`、换行 → 空格。iwara 标题自带竖线很常见（「A | B」型），不转义会多出一列、整行右移——链接被挤出表格或看似为空，表现为「没链接」（实际都在文件里）。
- 标签列截断为前 8 个 + 「(+N)」，避免行宽失控。
- 交付前程序化校验：逐数据行按 `|` split，断言字段数等于该节预期列数、最后一个实单元格以 http 开头。别靠肉眼——几百行的表错位肉眼发现不了。

用户问「怎么搜更多」时：先查论坛全量帖 + 官方 Search Operators 公告再给方法说明。
